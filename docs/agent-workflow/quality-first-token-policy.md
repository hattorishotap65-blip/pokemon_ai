# Quality-first token policy

## 目的

このポリシーの目的は「短さ」ではない。**重複を除きながら、判断品質を維持すること**が目的である。トークン節約は、判断の正確性・根拠・リスク認識を犠牲にしてはならない。曖昧さや情報欠落が生じる場合は、常にトークン節約より完全なコンテキストを優先する。

このポリシーは [`subagents.md`](subagents.md) の4エージェント（requirements-auditor / simplifier / claude-architect / design-judge）と、[`review-protocol.md`](review-protocol.md) の基本フローに適用する。Step 6以降で追加されるSkillにもこのポリシーを継承する。

## 削減してよい情報

- 重複するコンテキスト（同じ事実を複数箇所へ再掲すること）
- 同じコード全文の再掲（パス・関数名・行範囲での参照に置き換える）
- 判断に不要なログ（成功ログの詳細な逐次出力）
- 前回案の全文再送（識別子と差分で代替できる場合）
- 判断に寄与しない不要なエージェント呼び出し（例: 対立がない場合のAlternative Architect）

## 削減してはいけない情報

- 必要な証拠（Confirmed/Inference/Unknownの区別とその根拠）
- 重大リスク
- Unknown（未確認事項。埋めずに明示する）
- テスト計画
- ロールバック方法
- 設計案の比較に必要な内容（利点・欠点・却下理由）

これらは、たとえ出力が長くなっても省略しない。品質低下につながるエージェント統合・要約・省略は行わない。

## リポジトリ直接参照

リポジトリ内のコード・文書は、可能な限りエージェントに直接読ませる（Read/Glob/Grepを使用する）。要約や伝聞で済ませず、一次情報を参照させる。

## 証拠IDと案ID

設計案・レビュー・証拠には識別子（Proposal ID、案A/案B/案C、Evidence ID等）を付け、以降の参照はこの識別子で行う。全文を毎回引用し直さない。

## 第2ラウンドでは差分を優先

review-protocol.mdの第2ラウンドは、新しい証拠・具体的な反証がある場合のみ実施する。その際も、前ラウンドの内容を全文再掲せず、変更点・追加証拠との差分を中心に提示する。同じ主張の繰り返しは禁止する（review-protocol.mdと同じ方針）。

## 成功ログと失敗ログの扱い

- **成功ログ**: 要点を要約してよい（何を確認し、結果がどうだったかが分かれば十分）
- **失敗ログ**: 原因究明に必要な部分を保持する。エラーメッセージ、失敗したコマンド、関連するスタックトレース・差分など、根本原因の特定に必要な情報を削らない

## 不要なAlternative Architectを呼ばない方針

Alternative Architect（review-protocol.md参照）は、重大な対立・追加案が必要な場合・またはユーザーが指定した場合にのみ使用する。通常時はMain ArchitectとIndependent Architectの2案比較で足りるため、追加呼び出しは行わない。これは推論能力を下げるためではなく、判断に寄与しない呼び出しを避けるためである。

## 制約

- hard token capを設定しない。厳しい文字数・トークン上限は設けない
- モデルのeffortを下げることで節約しない。effortは固定しない
- 推論能力を下げる要約・省略は行わない
- 情報不足・曖昧さが生じる場合は、トークン節約より完全なコンテキストを優先する

## Step 6での継承

Step 6で追加予定のmulti-agent-design Skillは、このポリシーをそのまま継承する。Skill側で新たな節約ルールを追加する場合も、このポリシーの「削減してはいけない情報」を緩めてはならない。
