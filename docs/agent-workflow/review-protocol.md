# レビュープロトコル

[README.md](README.md) の基本フローに対応する、設計討論とレビューの具体的な手順。役割の定義・現在の希望割り当ては README.md を参照。

## タスク入力フォーマット

マルチエージェントワークフローで扱うタスクは、着手前に以下を明示する。

- 目的
- 背景
- 対象範囲
- 対象外
- 変更可能ファイル
- 変更禁止ファイル
- 制約
- 受入条件
- 検証コマンド
- 実装の可否
- commit / push / PRの可否

**情報が不足している場合、エージェントが勝手に補完してはならない。** 不足している項目は「確認事項」として明示するか、その項目を `Unknown` として扱い、埋めずに報告する。

## 証拠の区分

設計討論・レビュー・監査における各重要な主張は、次のいずれかに分類する。

- **Confirmed** — コード、設定、テスト、コマンド結果で確認済み
- **Inference** — 確認済みの事実からの推論
- **Unknown** — 現時点で確認できない事項

`Confirmed` の主張には、可能な限り以下を付ける。

- ファイルパス
- 関数名
- 行番号
- 実行コマンド
- テスト結果
- ログの該当箇所

**実行していないテストを「成功」と書くことは禁止する。**

## 独立提案

独立提案の提出者は、最低限以下とする。

- Primary/Main Architect（Sonnet）
- Independent Architect（Codex Terra）

Alternative Architect は、重大な対立・追加案が必要な場合・またはユーザーが指定した場合にのみ追加する。

各設計者は、**他の設計者の案を見る前に**独立して設計案を作成する。

各案には以下を含める。

- 前提
- 変更箇所
- データフロー
- 利点
- 欠点
- リスク
- 失敗時の戻し方
- テスト方法
- 未確認事項
- 変更しないもの

## レビューラウンド

設計討論は**最大2ラウンド**とする。

### 第1ラウンド

- 各案の独立提出
- 相互批評
- Red Teamレビュー
- 反論と修正版

### 第2ラウンド

- **重大な未解決事項がある場合のみ実施**
- **新しい証拠または具体的な反証がある場合だけ**反論可能

同じ主張の繰り返しは禁止する。

**2ラウンド終了後も重大な問題が残る場合は、実装へ進まずユーザーへ報告する。**

## 匿名評価

Design Judge へ渡す際は、可能な範囲でモデル名を除外し、「案A」「案B」「案C」として評価する。

評価基準（100点満点）:

| 基準 | 配点 |
|---|---:|
| 正確性 | 30点 |
| 根拠の強さ | 20点 |
| 安全性と変更範囲の遵守 | 20点 |
| 単純さ・保守性 | 15点 |
| テスト可能性・ロールバック性 | 15点 |

**単純な多数決ではなく、評価理由と重大な懸念を記録する。**

## 統合設計

統合設計は、**Design Judge / Integrator（Opus）が匿名評価の結果を基に作成する。**

統合設計には以下を含める。

- 採用する案
- 採用しない案と理由
- 対象ファイル
- 変更順序
- 各変更の目的
- テスト計画
- ロールバック方法
- リスク
- 未確認事項
- ユーザー承認が必要な事項

**Implementation Owner（Sonnet）は統合設計を変更しない。** 実装中に不明点や実装不能な事項が判明した場合は、実装前に作業を停止し、ユーザーへ報告する。

## 実装権限

原則として**コードを変更できるのは Implementation Owner（Sonnet の希望割り当て）だけ**とする。他のエージェントは read-only。

### 他のエージェントが行ってよいこと

- コードの読取り
- 検索
- 分析
- 設計案作成
- レビュー
- テスト結果の評価
- diffの監査

### 行ってはいけないこと

- アプリコードの編集
- 設定値の変更
- 方策・スコアの変更
- commit
- push
- PR作成
- merge

ただし、**ユーザーが特定の作業について明示的に別の担当を指定した場合は、その指示を優先する。**

## 実装前ゲート

次がすべて揃うまで実装へ進まない。

- 対象範囲が確定
- 変更禁止範囲が確定
- 統合設計が完成
- 重大なUnknownが解消または明示
- テスト計画がある
- ロールバック方法がある
- ユーザーが実装を承認

**設計のみの依頼では、このゲートを通過しても実装しない。**

## 最終監査

Final Auditor（Codex Sol Extra High の希望ロール）は、実装後に以下を確認する。

- 統合設計との一致
- 対象外ファイルの変更
- 不要な依存追加
- 秘密情報
- テスト不足
- 未処理の例外
- 後方互換性
- パフォーマンス回帰
- 方策・スコア・選択結果への意図しない影響
- ドキュメントと実装の不一致

**最終監査者はコードを修正せず、指摘と判定だけを返す。**

## 停止条件

次のいずれかに該当する場合は作業を停止する。

- 作業ツリーに未確認の変更がある
- 指示外のファイル変更が必要
- 秘密情報を扱う必要がある
- 対象モデルやツールが利用できない
- テスト方法が確認できない
- 既存文書と実装が矛盾している
- 重大なUnknownが残る
- 2ラウンド後も設計が収束しない
- ユーザー承認が必要
